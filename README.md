# NoseWiper 🎬

**Telegram-бот, который решает, что посмотреть вечером:** подбирает случайный фильм
с Кинопоиска, ведёт личную коллекцию пользователя и вытаскивает из неё фильм наугад,
когда выбрать самому невозможно.

## Задача

Классическая проблема вечера: список «посмотреть потом» лежит в заметках, вкладках
и скриншотах, а когда доходит до дела — выбрать невозможно. Бот собирает коллекцию
в одном месте и берёт выбор на себя.

## Что умеет

| Команда | Что делает |
|---|---|
| `/random` | Случайный фильм с Кинопоиска с рейтингом выше 6 — с постером, жанрами и описанием |
| `/wisechoice` | Случайный фильм из личной коллекции пользователя |
| `/add` | Добавить фильм в коллекцию по ссылке с Кинопоиска |
| `/del` | Удалить фильм из коллекции |
| `/cancel` | Выйти из текущего сценария |

Под карточкой фильма — инлайн-кнопки: добавить в коллекцию, удалить, показать ещё один
случайный фильм. Коллекция у каждого чата своя.

## Технические решения

- **Диалоговые сценарии через состояния.** Команды `/add` и `/del` ждут следующего
  сообщения со ссылкой: состояние пользователя хранится в памяти и определяет,
  как трактовать входящий текст.
- **Кеширование фильмов в БД.** Карточка, полученная от API, сохраняется локально —
  повторные показы фильма из коллекции не тратят запросы к внешнему API.
  Вставка идёт через `INSERT OR IGNORE`, связка «чат — фильм» защищена `UNIQUE`,
  так что дубликатов не появляется.
- **Устойчивый разбор ответа API.** Поля ответа Кинопоиска разбираются с проверкой типов,
  у названия есть фолбэк на альтернативное — отсутствующее поле не роняет бота.
- **Обход лимита Telegram.** Подпись к фото ограничена 1024 символами: длинное описание
  отправляется отдельным сообщением после постера.

## Стек

| Слой | Технологии |
|---|---|
| Язык | Go 1.26 |
| Telegram | `go-telegram-bot-api/v5` (long polling) |
| Хранилище | SQLite (`mattn/go-sqlite3`), чистый SQL без ORM |
| Внешний API | Кинопоиск (`kinopoisk.dev`) |
| Конфигурация | `godotenv` |

## Архитектура

```
cmd/bot/main.go        — точка входа: конфиг, инициализация БД, цикл обновлений
internal/
├── handlers/          — обработка сообщений и инлайн-кнопок, сценарии диалога
├── api/               — клиент Кинопоиска и разбор ответа в доменную модель
├── db/                — схема SQLite и запросы: фильмы и коллекции пользователей
├── models/            — доменная модель Movie
└── state/             — состояния пользователей для многошаговых сценариев
```

Поток данных: `main` поднимает БД и long polling → каждое обновление уходит
в `handlers` → обработчик либо отвечает из `db`, либо идёт в `api` и кеширует результат.

## Запуск

1. Клонировать репозиторий:

```bash
git clone https://github.com/moritys/nosewiper.git
cd nosewiper
```

2. Создать `.env` в корне:

```
TG_BOT_TOKEN=токен от @BotFather
KP_TOKEN=ключ API kinopoisk.dev
```

3. Запустить:

```bash
go run ./cmd/bot
```

База `movies.db` создаётся автоматически при первом запуске.
